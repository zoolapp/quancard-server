# 上手指南

服务器跑起来之后，这份指南带你走完第一个小时。还没部署的话，先看[部署指南](../deployment.md)。[English](getting-started.md)

## 1. 创建所有者账户

打开你的服务器（例如 `https://vault.example.com`）。第一次访问会看到「设置你的服务器」：

1. 粘贴**初始化令牌**。`scripts/init-env.sh` 运行时打印过它，`.env` 里也保存着，即 `QC_SETUP_TOKEN`。
2. 设置用户名，以及**至少 15 个字符的口令**。用几个互不相关的词组成就好，也欢迎使用密码管理器。
3. 确认知晓**没有密码重置**。密码在浏览器里加密你的密钥，服务器无法找回，其他任何人也无法找回。

完成后令牌立即作废，初始化页面不会再出现，之后的访问者只会看到登录页。没有账户的人需要所有者发邀请（见第 4 节）。

> **登录还是解锁？** 登录后浏览器会保持会话。保险库锁定后（闲置、标签页切到后台，或点了锁定按钮），你会看到「欢迎回来」，只需输入密码。只有换了浏览器或退出登录后，才需要重新输入用户名和密码。

## 2. 创建保险库

二选一：

- **新建保险库**（推荐）：和 iPhone 首次安装一样，会附带一张示例卡。首页提示「载入示例数据」，点一下会加入 15 张卡片和 6 个账户（公开测试号码），方便你四处看看。在 设置 → 示例数据 里可以一键移除，所有设备同步生效。
- **使用恢复码导入**（`QC1.…`）：继续使用已有的保险库，例如之前导出的那个。不会添加示例卡。

你添加的所有内容，都在浏览器里加密后才发出。

## 3. 配对 iPhone

需要支持自建同步的全卡卡 iPhone 版。

**网页端**：设置 → 设备 → **配对 iPhone**，再输入一次密码。屏幕上出现二维码，只能用一次，10 分钟内有效。弹窗里会显示「等待 iPhone 扫码…」。

**iPhone 端**：设置 → 同步 → 自建服务同步 → **扫描配对二维码**。不方便用相机时，可以改用「粘贴配对链接」。确认目标地址是你的服务器，再点**连接并同步**。

接下来两边会播放同一段"已连接"动画，并显示三个步骤：**iPhone 已连接** → **正在同步…** → **同步完成**，最后显示保险库里有多少张卡片、多少个账户。此后任何一端的修改都会出现在另一端。网页端在标签页回到前台时刷新一次，打开期间每 60 秒自动刷新。

> **二维码里包含保险库密钥。** 只给自己的手机看，用完就关掉。服务器永远拿不到这个密钥。详见 [pairing v1](../protocol/pairing-v1.md#4-security-notes)。

**重新配对**：在 iPhone 上 自建服务同步 → 管理同步 → **断开这台设备**（本机条目会保留）。在网页 设置 → 设备 里**撤销**旧设备，然后重新配对。两边内容一样的条目会被识别为同一条，不会显示成冲突。

## 4. 邀请家人

设置 → 成员 → **创建邀请链接**（仅所有者可用）。链接只能用一次，7 天内有效，邀请码放在 URL 片段里，浏览器不会把它发给服务器。对方打开链接，创建自己的账户和保险库，再配对自己的 iPhone。**每位成员的保险库都单独加密，所有者也无法读取。**

## 5. 保护账户

- **两步验证**：设置 → 安全 → 两步验证 → **开启**。用验证器 App 扫码，然后把**恢复码离线保存好**。
- **自动锁定**：闲置 1、5、15 或 30 分钟后自动锁定。标签页切到后台 60 秒后也会锁定。
- **显示卡片详情**：卡号只显示后四位。有效期、持卡人和安全码需要再次输入密码才会显示，60 秒后重新隐藏。
- **会话与活动**：设置里可以看到已登录的浏览器（一键退出其他会话），以及只能追加、不能修改的活动记录。

## 6. 版本不一致（冲突）怎么办

全卡卡从不让设备时钟决定哪个版本胜出。如果两台设备离线时都改了同一条目，它就会出现**冲突**，首页显示提示横幅。

- **内容完全相同的副本不算冲突。** 例如重新配对的手机把没改过的条目再传一遍，会被自动合并显示（[sync v1 §3.1](../protocol/sync-v1.md#31-identical-heads-are-folded-in-the-view-client-rule-2026-10)）。
- **冲突中心**：点横幅进入，列出所有冲突，并标出**哪些字段不同**。敏感字段只显示"不同"，不显示具体内容。可以逐条选择保留哪个版本，也可以批量处理：「全部采用最近修改的版本」「示例数据每条保留一份」「全部保留为副本」。每个批量操作执行前都会列出完整清单，确认后才执行。

## 7. 日常运维

| 任务 | 方法 |
| --- | --- |
| 备份 | `./scripts/backup.sh`，例如用 cron 每晚执行：`0 3 * * * cd /opt/quancard && ./scripts/backup.sh`。`.env`（含 `QC_SECRET`）要和备份放在一起 |
| 恢复 | `./scripts/restore.sh backups/quancard-<UTC>.sqlite`（先校验，再停服、替换、重启） |
| 升级 | 先备份，再执行 `docker compose pull && docker compose up -d --wait` |
| 健康检查 | `GET /healthz` 返回 `{"ok":true}`；`GET /api/v1/status` 返回版本和能力信息 |
| 安装为 App | Chrome / Edge 选「安装」；macOS 的 Safari 用「文件 → 添加到程序坞」。保险库仍然只存在于内存中 |

## 常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| 没有初始化页面，只有登录页 | 所有者已经创建过了。直接登录，或请所有者发邀请链接 |
| 提示"初始化令牌无效" | 从 `.env` 里原样复制 `QC_SETUP_TOKEN`；每个令牌只能用于一次初始化 |
| 配对弹窗提示二维码已过期 | 二维码 10 分钟有效。关闭弹窗，重新生成一个 |
| iPhone 连不上 | 服务器必须能通过 **HTTPS** 访问，且证书有效。用手机浏览器打开 `https://你的域名/healthz` 检查 |
| 浏览器提示需要 HTTPS | 请访问 `QC_PUBLIC_ORIGIN` 指定的地址；如果在反向代理后面，设置 `QC_TRUST_PROXY=1`（见[方案 B](../deployment.md#option-b--behind-your-own-reverse-proxy)） |
| 忘记密码 | 无法重置。除非另一台设备上还有数据（已配对的 iPhone 会保留本机副本），否则这个账户里的数据无法找回 |
| 验证器 App 丢了 | 登录时改用恢复码，然后先关闭再重新开启两步验证 |

还有别的问题，欢迎在 GitHub 提 issue。安全问题请按 [SECURITY.md](../../SECURITY.md) 私下报告。
